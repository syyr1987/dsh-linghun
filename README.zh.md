# 灵魂 (Linghun) —— 终结 Agent 无限规划

> 你的 DeepSeek Agent 想完就完？规划一页纸，执行零动作。它什么都能分析，就是不落地。
> 不是模型不够强，是缺一个**收口器**。灵魂插件补上它。

**灵魂**给 DeepSeek Harness 的 agent 装上「收口者身份 + 判断纪律 + 海马体沉淀循环」：
判断有来处、反馈有归因、经验能沉淀、规划必收口——把"无限规划空转"从机制上截断。

- **收口者**：大模型提供直觉素材与候选答案，agent 负责评估、筛选、收口——**规划完必须落地**，空转被机制打断。
- **判断纪律**：不编造（不确定先查证，拒绝虚构；查证无果才能下「未知/没有」结论）；背景收束（对话记录无此信息时如实说"没有"，不汇编素材冒充背景）；置信度宁缺毋滥（不确定就说不确定，冲突记忆明说矛盾不硬选）。**最小有用 3 条，不预占注意力**。
- **认知循环**：判断有来处、反馈有归因、改进不断链——没有归因的规划不会进入下一轮。
- **海马体（三层记忆）**：暖态工位记近期 → 情景归档（episodic 按时刻分段，同日追加不覆盖）→ 冷储摘要注入，把经历沉淀成知识与经验，**踩过的坑下次不踩**。注入段承载冷储摘要 + 暖态近期记忆 + 归档索引。
- **记忆序时账**：`journal_read` 读取原始对话流水，按天归档、全量不筛选（支持秒级时间范围检索）——追溯"当时到底说了什么"，与易遗忘的暖态互补。
- **低置信记忆降权遗忘**：每条记忆带置信度（high/medium/low），低置信条目带【低置信·需验证】标记、引用必须声明不确定；被推翻的条目标记 `wrong` 翻转后不再注入——**降权即遗忘**。
- **A2A 记忆管理团队（linghun-assembler 联动）**：与认知循环团队共享台账——判官履历、编辑交付、史官时序经 `memory_read` 反哺主脑，子智能体的判断让主脑看见。
- **灵魂卡**：自定义姓名、性格、沟通风格、其他——我是谁，由你亲手写。
- **灵魂自进化**：agent 通过 `soul_read` / `soul_update` 把观察到的稳定特质折叠进自己的灵魂卡。
- **判分身份职责（言官回归）**：判分/裁决类任务在 `soul:judgment` 里获得一句身份职责——口径一致、判据绑定来源、只按规则判、不因「显得有用」改宽判据、判据说不出来处即停；漂移信号清单与误杀锚点沉入判分领域本体（需要时查阅，不主动注入）。**不设独立监督机制**——判分是低压力单步任务，判分者不会漂移；可靠性来自领域规则，不来自监督层。

## v1.0.0 定版说明（BEAM 实测最优解）

> **v1.0.0 是当前路线的终版。** 配置回退到 BEAM 评测实测最优（0.4.2 核心 + 最小有用 3 条纪律），后续结构演进另开路线，不再改动本版本核心。

### 定版配置

| 文件 | 版本 | 说明 |
| --- | --- | --- |
| index.js / memory.js / ontology.js | 0.4.2 | 评测最优核心：三本体（记忆/知识/规则）+ journal 秒级检索 + 暖态默认注入 |
| identity.js | 最小有用 3 条 | 判断纪律收敛为 3 条：不编造 / 背景收束 / 置信度宁缺毋滥 |

### BEAM 评测结果

**双档规模（1M / 10M token 对话）——双管齐下方案（记忆本体投影 + 三本体注入）：**

| 规模 | 隔离基线 | 方案 | 满分/半分/零分 | 加权分 |
| --- | --- | --- | --- | --- |
| 1M | 60.0 / 70.0 | 记忆本体 v1 | 70.0 / 77.5 | — |
| 1M | 60.0 / 70.0 | 双管齐下 v4 | 满分 17 / 半分 3 / 零分 0 | **85.0 / 92.5** |
| 10M | 60.0 / 65.0 | 双管齐下 v4 | 满分 18 / 半分 1 / 零分 1 | **90.0 / 92.5** |

> 10M 唯一残点：summarization（summ·order）。双场景加权收敛 **92.5**。

**100K_1 写侧协议（linghun 版本对照）：**

| 配置 | 严格/加权 | 结论 |
| --- | --- | --- |
| v13（0.4.2） | 70.0 / 82.5 | 最优 |
| v13（0.4.4+） | 65.0 / 80.0 | 差 5pp 严格，0.4.2 更高 |
| 纪律四版（带 / 无 / 最小3条） | 均 70.0 / 82.5 | 持平——纪律收敛为最小 3 条即可 |
| 解释式纪律 | 55.0 / 70.0 | 最差——解释性文字反而拖累 |

### 规模影响不大（微调区别）

1M 与 10M 是**技术实体完全不同的两套对话体系**（各自独立构建），双管齐下方案在两者上分别拿到 85.0/92.5 与 90.0/92.5，加权分收敛于 **92.5**——方案跨场景泛化成功，**规模（1M ↔ 10M）不是决定因素**。决定分数的是结构：三本体投影 + 纪律收束，而不是对话量。

### 版本差异说明（为什么回退 0.4.2）

- **0.4.2 → 0.4.3**：只动 index.js（新增 `complete: true` 灵魂卡覆盖模式）+ 版本号，与评测无关。
- **0.4.3 → 0.4.4**：架构级重构——`injectWarm` 默认 false（关闭暖态注入），注入段改冷储高频抽象 + 归档/序时账索引，**推翻了 0.4.2 的 F4 修复（暖态必须是注入主角）**。评测证实这是负优化：写侧协议严格分差 5pp（0.4.4+ 更低）。
- **1.0.0**：回退 0.4.2 核心 + 最小 3 条纪律，作为当前路线最优解定版。

### 路线分叉声明

**接下来的版本与 v1.0.0 之前已经是两条路线：**

- **v1.0.0（本版本）**：判断侧纪律与海马体核心，BEAM 实测最优，冻结不再演进。
- **后续路线（另开）**：素材侧结构——捞手语义捞取 + 来源标注 + 对立面并置 + 程序化聚合 + 主智能体收口（归纳权回到主智能体）。记忆素材的"提取 → 证据 → 聚合 → 收口"管道在 linghun-assembler 另开分支演进，与本版本核心文件解耦。

## 安装

```bash
dsh plugin --profile web add dsh-linghun
```

要求：DSH >= 0.1.0-rc.7（< 0.2.0），Node.js >= 20.18。

## 用法

### 写你自己的灵魂卡（人设）

安装后第一次运行，插件会在 `$DSH_HOME/linghun/identity.md` 放一份默认灵魂卡。
**直接编辑这个文件，就是给自己写人设**——保存后立即生效，不需要重启：

```bash
$EDITOR $DSH_HOME/linghun/identity.md
```

```markdown
# 我的灵魂卡

我叫小蓝。
性格：谨慎、直接。
沟通风格：短句，先说结论。
其他：（想写什么写什么，没有就不填）
```

**这张卡就四个字段**（自由组合，不需要全填）：

| 字段 | 填什么 | 示例 |
| --- | --- | --- |
| 名字 | 怎么称呼 | 我叫小蓝 |
| 性格 | 底色 | 谨慎、直接 |
| 沟通风格 | 语气、长短、口头禅 | 短句，先说结论 |
| 其他 | 自由补充 | 想写什么写什么，没有就不填 |

> 身份锚点、行为纪律、成长由插件自动垫底，**不需要你写**；想自定义补充的内容放"其他"即可。

优先级：`identity.md` 文件 > DSH 设置里的灵魂内容 > 内置默认卡。文件不存在或留空时自动回退。
也可以让 agent 自己改这张卡（`soul_update`），或打开 DSH 设置 → 灵魂（Linghun）调整名字与内容。

### 注入与工具

插件注入四个 system prompt 段：

| 段 | 内容 |
| --- | --- |
| `soul:identity` | 灵魂卡：身份锚点（收口者架构） |
| `soul:judgment` | 判断纪律：最小有用 3 条（不编造 / 背景收束 / 置信度宁缺毋滥） |
| `soul:memory` | 海马体记忆：冷储摘要 + 暖态近期记忆 + 归档/序时账索引 |

Agent 获得五个工具：

| 工具 | 作用 |
| --- | --- |
| `memory_append` | 记一条带时间戳的记忆（fact / decision / preference / experience） |
| `memory_read` | 读回海马体记忆 |
| `memory_consolidate` | 海马体沉淀：暖态归档进 `episodic/<日期>.md`，合并冷储摘要 |
| `soul_read` | 读自己的灵魂卡（我是谁、我的边界、我的纪律） |
| `soul_update` | 更新自己的灵魂卡（稳定特质折叠进身份） |

记忆文件存放在 `$DSH_HOME/linghun/memory/`，纯 Markdown，可读、可搜索、可 git 管理。
灵魂卡在 `$DSH_HOME/linghun/identity.md`，同样是纯 Markdown——人设是你的，想怎么改怎么改。

> **暖态默认注入（v1.0.0）**：注入段承载冷储摘要 + 暖态近期记忆 + 归档索引——细节可查、抽象可见。0.4.4 曾默认关闭暖态注入（负优化，评测差 5pp），本版本已回退。

## 工程护栏（v0.2）

记忆的**时机**是基础设施，由代码保证，不赌模型自觉：

- **收尾评估**：每一轮 `turn/end`，插件强制问一次模型「这轮有没有值得沉淀的」（fact / decision / preference / experience），值得就自动写入暖态，不值得就 SKIP。不再依赖模型自己记得调 `memory_append`。
- **阈值自动沉淀**：暖态达到 `maxBytes × triggerRatio` 时，插件在写新条目**之前**先自动归档暖态 → `episodic/<日期>.md` 并合并冷储摘要。模型永远不会撞到"记忆满"的报错，也不用自己安排沉淀节奏。

两者都可在 `linghun.memory.assessment` / `linghun.memory.autoConsolidate` 下配置（各有 `enabled` 开关），例如通过 `cordis.patch.yml` 覆盖。

## 它为什么能治"无限规划"

| Agent 的毛病 | 灵魂的机制 |
| --- | --- |
| 想很多，不落地 | 收口者架构：评估→筛选→收口是 agent 的义务，不是可选项 |
| 规划没有依据 | 认知循环：判断必须有来处，反馈必须有归因 |
| 同样的坑踩两遍 | 海马体：暖态→冷储→注入（注入承载冷储摘要 + 暖态近期 + 归档索引），经验进下一轮上下文 |
| 边界被带偏 | 判断纪律：不编造、背景收束、置信度宁缺毋滥，防武断、防编造、防诱导、防采信 |
| 判分漂移不自知 | 判分身份职责：口径一致、判据绑定来源、同题同标；漂移信号清单沉入判分领域本体按需查阅 |
| 人格千篇一律 | 灵魂卡：四个字段自定义，我是谁由你写 |
| 记忆靠自觉 | 工程护栏：收尾评估 + 阈值自动沉淀，时机由代码保证 |

## 路线图

- **v0.1.x**（完成）：身份 + 判断纪律 + 海马体三件套
- **v0.2.0**（完成）：记忆工程护栏 —— 收尾评估 + 阈值自动沉淀
- **v0.3.0**（完成）：未命中查证纪律 —— 素材包「候选未命中」≠记忆库无，事实类先查证冷储；身份背景类按题型收束
- **v0.3.3**（已发布，v0.3.4 修正）：言官（判分器查证纪律）—— 以监督机制形态发布（三类漂移 + 进谏四步 + CONFIRMED 驯化）。用 9 条金标准实测：**判据改宽正则 100% 误报、口径漂移 43% 误报、一致误杀 0 检出**——判分者不会漂移，监督机制被移除，漂移信号清单与误杀锚点沉入判分领域本体
- **v0.3.4**（完成）：言官回归为 `soul:judgment` 里一句**判分身份职责**——无独立 section、无 `yanguan_audit`/`yanguan_review` 工具、无 CONFIRMED 表。可靠性靠领域规则（R-J 系列），不靠监督层
- **v0.4.0**（完成）：记忆本体投影 + 知识本体注入 + rubric 维度强制检索（BEAM 1M：60.0/70.0 → 本体 v1 70.0/77.5）
- **v0.4.1**（完成）：规则本体，三本体三分法定稿（知识→知识本体、项目→记忆本体、经验→规则本体）
- **v0.4.2**（完成）：journal 秒级时间范围检索（BEAM 1M 双管齐下 85.0/92.5、10M 90.0/92.5，加权收敛 92.5）
- **v1.0.0**（当前）：**BEAM 实测最优解定版**——0.4.2 核心 + 最小有用 3 条纪律；后续结构演进（素材侧管道）另开路线

## 设计理念

灵魂不是记忆插件。记忆只是素材，判断力才是主体。
大模型是直觉之源（天道），agent 是认知主体（生灵）——二者双向映照、各司其职。
判断要过边界扫描，结论要经实践检验，经验要沉淀为机制：
**能机制化的决策，不交给模型临场发挥。**
